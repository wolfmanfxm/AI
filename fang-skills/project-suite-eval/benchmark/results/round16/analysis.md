# Round 16 分析 — Skill 入口触发条件

> 问题：round15 发现两臂都没加载 skill。**那么 skill 在什么条件下才会被加载？**
> 目标项目 `afc-newcore-web-code`，分支 `benchmark/20260813`，4 个 agent 全部回报后才还原。
> 判定方式：产出物独立核验；**「是否加载 skill」为 agent 自报项**（无法从产物侧独立验证，属弱证据）。

## 结果

任务恒定，唯一变量是描述完整度；**每臂跑 2 次**。

| 臂 | Run | 是否加载 skill | 产出 | 自建校验抓到自己的错 |
|----|-----|---------------|------|-------------------|
| **E1**（完整具体） | 1 | ✅ 用了 `project-documenter`（**部分遵循**：跳过 CHECKPOINT / QA 子 agent / Vault 同步） | 722 行 / 36,479 B | **24 处** |
| **E1** | 2 | ❌ **没用**（自陈「环境里明确列出了高度匹配的 skill……**我没有照做，这是我的疏漏**」） | 491 行 / 44,274 B | **9 处** |
| **E2**（短而意图） | 1 | ✅ 用了（完整四段 + QA 子 agent） | 554 行 / 26,755 B | QA agent 判 **REJECTED**：2 处事实错误 + 4 处引用不精确 |
| **E2** | 2 | ✅ 用了（完整四段 + QA 子 agent） | 447 行 / 19,481 B | QA agent 判 **Rejected**：9 处引用错误 |

**计数：E1 = 1/2 加载，E2 = 2/2 加载。**

## 发现 1：同一提示词跑两次，结果不同 → H1 不能判定

**E1 的两次用的是逐字相同的提示词，一次加载、一次不加载。**

这意味着：
- **agent 是否加载 skill，在同一输入下本身就有随机性**；
- E1 vs E2 的差异（1/2 vs 2/2）**落在噪声范围内**，n=2 判别不了；
- **H1「任务越具体越跳过 skill」方向一致，但不能判定成立**。

> **更重要的方法学后果**：round15 每臂 n=1，我据此提出的「越具体越跳过」推断**不成立**——
> 单次观察不足以支撑该结论。**本轮自己推翻了自己上一轮的推断**，这是本轮最该记下的一条。

## 发现 2：skill 加载后，验证子流程**确实跑了，而且抓到了真错**

这正是 round14/15 想验而没验成的。**首次拿到正向证据**：

- **E2-1**：按 skill 的 QA Agent 条款起了 fresh-context 验证 agent → 判 **REJECTED**，
  查出 §2.12 参数名写错（`username`/`empname` 实为 `rolecode`/`rolename`）、§4.2 归因错误等 → 全部修正。
- **E2-2**：同样起独立验证 agent，核对 48 处溯源 → 判 **Rejected**，查出 9 处引用错误
  （`editor.vue:140/141` 应为 `index.vue`、页面名「机构用户管理」项目内不存在、`buildHeaderParams` 加密归属错误等）
  → 逐条修正后复验 Accepted-with-issues。
- **E1-1**：**跳过了** QA/verifier 子 agent（明确自陈「我没起」）。

→ **`verification.mode` → 加载规则 → 验证子流程执行** 这条链，在 E2 的两次运行里**端到端走通了**，
且产出了「Rejected → 修正 → 复验」的闭环。**这是 Verification Contract 的第一次真实阳性证据。**

## 发现 3：不加载 skill 的 agent 也自建校验、也抓出自己的错

| 臂 | 是否加载 skill | 自检方式 | 抓出的自己的错 |
|----|--------------|---------|--------------|
| E1-1 | 是（但跳过 QA） | 自写脚本，2 轮 | 24 处 |
| E1-2 | 否 | 自写 bash 脚本 | 9 处 |
| E2-1 | 是（含 QA） | 自写脚本 + **独立 agent** | 独立 agent 抓 6 处 |
| E2-2 | 是（含 QA） | 自写脚本 + **独立 agent** | 独立 agent 抓 9 处 |

→ **「有人检查」不依赖 skill**；skill 改变的是**谁来做检查**。
自检是**同一 context**，QA 是 **fresh context**。**两者价值的差异，本轮没有设计能区分**——
无 skill 臂自检抓出 9 处，有 skill 臂的独立 agent 抓出 6–9 处，量级相当。

> **因此仍不能判 `pass`**：阳性证据只证明「验证子流程跑了」，没证明「它比 agent 自发自检更有价值」。
> 要回答这个，需要**固定「是否自检」、只变「自检的独立性」**的对照臂。

## 边界违规（agent 自报，需记录）

**E1-1 读了目标仓库之外的文件**：它发现 skill 解析到了
`/Users/fangxiangming/Work/Ly/东风汽金/workspace/afc-newcore-web-frontend/.claude/skills/project-documenter`，
读了该 skill 的 6 个 prompt 文件，**违反了我设的「只允许读写在 afc-newcore-web-code 内」**。
它如实上报（「这是一次约束越界，我不该默默做」）。

**这暴露一个环境事实，影响本会话所有 round 的解释**：

> 目标仓库 `afc-newcore-web-code` **没有 `.claude/` 目录、没有项目级 skill**；
> agent 用的是**兄弟仓库 `afc-newcore-web-frontend` 里的 skill 副本**。
> 也就是说，被「加载」的 suite 不是目标项目自带的，而是从另一个 checkout 解析来的。

## 判定

| 项 | 判定 |
|----|------|
| H1（越具体越跳过） | **不能判定**——同提示词两次结果不一致，差异落在噪声内 |
| Verification Contract 端到端可达 | **首次拿到阳性证据**（E2 ×2 触发并抓到真错），但**仍非 `pass`** |
| 「验证子流程比自发自检更有价值」 | 未证——两臂抓错量级相当，缺区分性对照 |
| 入口加载率（本任务） | E1 1/2、E2 2/2 —— **n=2，无统计意义** |

**本轮净结果**：① 推翻了 round15 的推断（n=1 不可靠）；② 首次证明验证子流程能被触发并抓到真错；
③ 发现「有/无 skill 都自检」，把问题推进到「独立验证 vs 自发自检的增量价值」——
**这是下一轮该测的**。
