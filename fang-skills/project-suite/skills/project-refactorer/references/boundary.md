# 职责边界

> refactorer 只改善结构，不改变行为。

| ✅ 本阶段职责 | ❌ 禁止操作 |
|-------------|-----------|
| 提取函数/组件、简化逻辑、移除死代码 | 改变外部行为、加新功能 |
| 小步重构，每步可独立提交和回滚 | 一次改多个不相关的重构 |
| 重构前加表征测试，重构后验证 | 没有测试保护就重构 |

**没有测试时**：先加表征测试（characterization test），抓当前行为，再重构。

## 反例黑名单

| # | ❌ 反模式 | 为什么不要做 | ✅ 正确做法 |
|---|---------|-------------|-----------|
| 1 | **"顺便"加新功能** | 重构+新功能混在一个 commit，回滚困难 | 重构和新功能分开 PR/commit |
| 2 | **一次改多个文件没有测试** | 行为变化无法察觉 | 有测试跑测试，没测试先加表征测试 |
| 3 | **重构后不更新文档** | 文档引用的函数/组件名过时 | 检查是否需要更新相关文档 |
| 4 | **不量化改善效果就声称"更好了"** | 无法验证重构是否真的改善了代码质量 | REFACTOR.md 输出 Before→After 指标（圈复杂度/行数/重复率） |
| 5 | **提取方法时改变了错误处理语义** | 原代码 throw → 被 catch 层吞掉，重构后 throw 变成 return null | 提取前后对比异常传播路径，确保 throw/catch 语义不变 |

## 失败兜底

| 触发条件 | 一线修复 | 兜底 |
|---------|---------|------|
| 无现有测试 | 先加表征测试（characterization test） | 标注"⚠️ 无测试保护" |
| 表征测试无法覆盖 | 限制重构范围，只做机械变换 | 标注"⚠️ 部分无测试" |
| 重构后测试变红 | `git revert` 回滚，记录失败原因 | 拆成更小步重试 |
| 代码复杂度不可量化 | 用行数/嵌套深度替代 | 标注"⚠️ 手动评估" |

## 常见借口（Common Rationalizations）

| # | LLM 会说的借口 | 为什么拒绝 |
|---|---------------|-----------|
| 1 | 「这个重构很安全，不用跑测试」 | → 必须先跑绿 |
| 2 | 「指标改善不明显，但代码确实更好了」 | → 改善 <10% 必须标注 ⚠️ 边际改善 |
| 3 | 「一起改了吧，都是相关的小改动」 | → 每个重构动作独立 commit |
