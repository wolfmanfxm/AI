# Doc Style Guide — Documenter

> 如何匹配项目已有文档风格。

## 风格检测

在写任何文档前，读 1-2 份项目已有文档，检测以下特征：

### 结构特征

| 检测项 | 示例 A | 示例 B |
|--------|--------|--------|
| 标题格式 | `# 一级标题` | `## 二级标题` 开头（无一级） |
| 标题层级数 | 3 级（`#` `##` `###`） | 2 级（`##` `###`） |
| 开头是否有目录 | ✅ 有 TOC | ❌ 直接开始 |
| 文件命名 | `UPPERCASE.md` | `kebab-case.md` |

### 内容特征

| 检测项 | 示例 A | 示例 B |
|--------|--------|--------|
| 语言 | 纯中文 | 中英混排 |
| 代码块标注 | ` ```typescript ` | ` ```ts ` |
| 代码块标题 | 有 `// src/xxx.ts` 标注 | 无标注 |
| 表格风格 | `| A | B |` 无对齐 | `| A   | B   |` 对齐 |
| 链接 | `[text](./file.md)` | `<text>` 尖括号 |
| Badge | 有 shields.io badge | 无 badge |

### 语气特征

| 检测项 | 正式 | 口语 |
|--------|------|------|
| 指令 | "请确保先阅读" | "先看看这个" |
| 说明 | "该函数用于" | "这个函数是" |
| 示例 | "示例如下" | "比如" |

## 风格匹配规则

1. **结构跟随已有** — 已有文档用什么标题层级，就用什么
2. **语言跟随已有** — 已有文档中英混排，你就中英混排
3. **不引入新元素** — 已有文档不用 Badge，你不加
4. **表格对齐跟随** — 已有文档对齐就对齐，不齐就不齐

## 无已有文档时

使用默认风格：
- `#` 一级标题，`##` `###` 二级三级
- 中文为主体描述，代码原文
- 代码块标注语言（` ```typescript `）
- 表格不强制对齐
- 语气正式但不僵硬
