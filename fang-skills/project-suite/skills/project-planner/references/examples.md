# Examples — Planner

> 真实输入 → 输出示例，展示 planner 的完整工作流。

---

## 示例 1：模糊需求 → 结构化计划

### 输入

> "我们 app 的搜索太慢了，用户反馈很多。帮我规划一下怎么优化。"

### 澄清过程

```
Q: 搜索涉及哪些数据？
A: 商品名称、描述、标签，还有订单历史

Q: 现在多慢？目标是多少？
A: 现在 3-5 秒，目标是 < 500ms

Q: 数据量级？
A: 商品 50 万，订单 200 万
```

### 输出（PLAN.md 摘要）

| ID | 任务 | 依赖 | 估时 | 优先级 | 风险 |
|----|------|------|------|--------|------|
| T1 | 搜索性能基准测试 + 瓶颈分析 | - | M | P0 | - |
| T2 | Elasticsearch 集群搭建 | - | L | P0 | 运维配合 |
| T3 | 商品数据索引 pipeline | T2→ | L | P0 | 数据量大，首次索引耗时 |
| T4 | 搜索 API 改造（MySQL→ES） | T1→, T3→ | L | P0 | - |
| T5 | 搜索建议/自动补全 | T4→ | M | P1 | - |
| T6 | 压力测试 + 监控告警 | T4→ | M | P1 | - |

## 示例 2：明确需求 → 直接拆解

### 输入

> "实现用户邀请注册功能：现有用户生成邀请链接，新用户通过链接注册后双方获得奖励积分。"

### 输出（PLAN.md 摘要）

| ID | 任务 | 依赖 | 估时 | 优先级 |
|----|------|------|------|--------|
| T1 | 数据库：invitations 表 + 积分记录表 | - | S | P0 |
| T2 | API：生成邀请链接（含过期时间） | T1→ | M | P0 |
| T3 | API：邀请注册接口（校验链接+创建用户） | T1→ | M | P0 |
| T4 | API：积分奖励逻辑（双方各+100） | T3→ | M | P0 |
| T5 | 前端：邀请链接生成+分享入口 | T2→ | M | P1 |
| T6 | 前端：邀请注册页面 | T3→ | M | P1 |
| T7 | 前端：积分到账提示 | T4→ | S | P2 |

依赖图：
```
T1 ─→ T2 ─→ T5
   ↘ T3 ─→ T4 ─→ T7
        ↘ T6
```
