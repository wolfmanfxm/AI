# Examples — Planner

> 真实输入 → 输出示例，展示 planner 的完整工作流。

---

## 示例 1：模糊需求 → 结构化计划

### 输入

> "我们 app 的搜索太慢了，用户反馈很多。帮我规划一下怎么优化。"

### 澄清过程

```
Q: 搜索涉及哪些数据？
A: 商品名称、描述、标签，还有订单历史

Q: 现在多慢？目标是多少？
A: 现在 3-5 秒，目标是 < 500ms

Q: 数据量级？
A: 商品 50 万，订单 200 万
```

### 输出（PLAN.md 摘要）

| ID | 任务 | 依赖 | 估时 | 优先级 | 风险 |
|----|------|------|------|--------|------|
| T-001 | 搜索性能基准测试 + 瓶颈分析 | - | M | P0 | - |
| T-002 | Elasticsearch 集群搭建 | - | L | P0 | 运维配合 |
| T-003 | 商品数据索引 pipeline | T-002→ | L | P0 | 数据量大，首次索引耗时 |
| T-004 | 搜索 API 改造（MySQL→ES） | T-001→, T-003→ | L | P0 | - |
| T-005 | 搜索建议/自动补全 | T-004→ | M | P1 | - |
| T-006 | 压力测试 + 监控告警 | T-004→ | M | P1 | - |

## 示例 2：明确需求 → 垂直切片拆解

### 输入

> "实现用户邀请注册功能：现有用户生成邀请链接，新用户通过链接注册后双方获得奖励积分。"

### 输出（PLAN.md 摘要）

| ID | Slice（完成后可观察行为） | 依赖 | 估时 | 优先级 |
|----|--------------------------|------|------|--------|
| T-001 | 生成邀请链接后页面展示可复制/分享的链接 | - | M | P0 |
| T-002 | 新用户打开链接完成注册并登录 | T-001→ | M | P0 |
| T-003 | 注册成功后双方积分到账并收到提示 | T-002→ | S | P0 |

依赖图：
```
T-001 ─→ T-002 ─→ T-003
```

> 每个 slice 内跨越「数据库表 / API / 前端页面」，收敛到一个可观察行为——不再按「数据库 → API → 前端」拆成 7 个任务。
