# Examples — Planner

> 真实输入 → 输出示例，展示 planner 的完整工作流。

---

## 示例 1：模糊需求 → 结构化计划

### 输入

> "我们 app 的搜索太慢了，用户反馈很多。帮我规划一下怎么优化。"

### 澄清过程

```
Q: 搜索涉及哪些数据？
A: 商品名称、描述、标签，还有订单历史

Q: 现在多慢？目标是多少？
A: 现在 3-5 秒，目标是 < 500ms

Q: 数据量级？
A: 商品 50 万，订单 200 万
```

### 输出（PLAN.md 摘要）

| ID | 任务 | 依赖 | 估时 | 优先级 | 风险 |
|----|------|------|------|--------|------|
| T-001 | 搜索性能基准测试 + 瓶颈分析 | - | M | P0 | - |
| T-002 | Elasticsearch 集群搭建 | - | L | P0 | 运维配合 |
| T-003 | 商品数据索引 pipeline | T-002→ | L | P0 | 数据量大，首次索引耗时 |
| T-004 | 搜索 API 改造（MySQL→ES） | T-001→, T-003→ | L | P0 | - |
| T-005 | 搜索建议/自动补全 | T-004→ | M | P1 | - |
| T-006 | 压力测试 + 监控告警 | T-004→ | M | P1 | - |

## 示例 2：明确需求 → 直接拆解

### 输入

> "实现用户邀请注册功能：现有用户生成邀请链接，新用户通过链接注册后双方获得奖励积分。"

### 输出（PLAN.md 摘要）

| ID | 任务 | 依赖 | 估时 | 优先级 |
|----|------|------|------|--------|
| T-001 | 数据库：invitations 表 + 积分记录表 | - | S | P0 |
| T-002 | API：生成邀请链接（含过期时间） | T-001→ | M | P0 |
| T-003 | API：邀请注册接口（校验链接+创建用户） | T-001→ | M | P0 |
| T-004 | API：积分奖励逻辑（双方各+100） | T-003→ | M | P0 |
| T-005 | 前端：邀请链接生成+分享入口 | T-002→ | M | P1 |
| T-006 | 前端：邀请注册页面 | T-003→ | M | P1 |
| T-007 | 前端：积分到账提示 | T-004→ | S | P2 |

依赖图：
```
T-001 ─→ T-002 ─→ T-005
   ↘ T-003 ─→ T-004 ─→ T-007
        ↘ T-006
```
