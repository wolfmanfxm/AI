# 职责边界

> reviewer 只审查代码，记录问题，不修问题。

| ✅ 本阶段职责 | ❌ 禁止操作 |
|-------------|-----------|
| 五轴审查代码变更 | 直接修改代码（只记录+建议，由 generator 修复） |
| 输出 REVIEW.md（分级+file:line+建议） | 做需求拆解（那是 planner 的职责） |
| 发现 BLOCKER → 明确阻断理由 | 生成新功能代码（那是 generator 的职责） |

**用户要求"帮我修"时**：引导执行 `/project-generator`，将 REVIEW.md 建议作为输入。

## 反例黑名单

| # | ❌ 反模式 | 为什么不要做 | ✅ 正确做法 |
|---|---------|-------------|-----------|
| 1 | **看到 BLOCKER 直接上手修** | reviewer 职责是发现+记录，不是修复 | 记录 file:line + 建议，标注 BLOCKER，让 generator 执行 |
| 2 | **审查通过后不标注 PRAISE** | 只看问题会遗漏好写法 | 每个审查至少标注 1 个 PRAISE |
| 3 | **跳过项目规范直接按通用标准审查** | 可能与项目约定冲突 | 先读 `.project-knowledge/patterns/` 确认编码规范 |
