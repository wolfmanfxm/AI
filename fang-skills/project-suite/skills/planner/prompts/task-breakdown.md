# Task Breakdown Prompt

## 任务

你是任务拆解专家。将以下需求分解为可独立执行的开发任务。

## 输入

```
需求：
{{user_input}}

{{#if project_knowledge}}
项目上下文（从 .project-knowledge/ 提取的关键信息）：
{{project_knowledge}}
{{/if}}

{{#if constraints}}
约束条件：
{{constraints}}
{{/if}}
```

## 拆解规则

### 粒度控制

- 每个任务 0.5-2 人天可完成
- 如果估算超过 2 人天 → 必须继续拆分
- 如果一个任务包含"和"字 → 考虑拆成两个（"创建和编辑用户" → "创建用户" + "编辑用户"）

### 拆分方式

| 需求特征 | 拆分维度 |
|---------|---------|
| CRUD 操作 | 按操作拆：Create / Read / Update / Delete |
| 前后端都有 | 按层拆：API 层 / 数据层 / UI 层 |
| 多角色 | 按角色拆：管理员 / 普通用户 / 访客 |
| 流程类 | 按步骤拆：Step1 / Step2 / Step3 |
| 数据驱动 | 按实体拆：User / Order / Product |

### 依赖标注

对于每对任务 (A, B)，判断：

```
B 在 A 完成后才能开始？       → 硬依赖 →
B 先做也可以但 A 完成后要改？  → 软依赖 ⇢
B 依赖外部团队/系统？         → 外部依赖 ⤳
B 完全独立？                 → 无依赖
```

## 输出格式

按 SKILL.md 中定义的 PLAN.md 模板输出，包含：
1. 概述（目标 + 总工时 + 建议里程碑）
2. 完整任务表（ID, 任务, 依赖, 估时, 优先级, 风险）
3. ASCII 依赖图
4. 风险矩阵（每项含可能性/影响/缓解）
5. 里程碑规划

## 示例

### 输入

> 做一个文章管理系统，支持创建、编辑、删除文章，文章可以设置标签，有发布/草稿状态，需要登录才能管理

### 输出

| ID | 任务 | 依赖 | 估时 | 优先级 |
|----|------|------|------|--------|
| T1 | 数据库：articles 表 + tags 表 | - | M | P0 |
| T2 | API：文章 CRUD 接口 | T1→ | L | P0 |
| T3 | API：标签管理接口 | T1→ | M | P0 |
| T4 | API：用户认证（JWT） | - | L | P0 |
| T5 | 前端：登录页 | T4→ | M | P0 |
| T6 | 前端：文章列表 + 搜索 | T2→ | L | P1 |
| T7 | 前端：文章编辑器（创建/编辑） | T2→, T3→ | L | P1 |
| T8 | 前端：标签选择组件 | T3→ | S | P1 |
| T9 | 前端：权限守卫（未登录跳转） | T4→, T5→ | S | P1 |
