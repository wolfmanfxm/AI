# Operating Modes

## `production` (default)

团队日常使用，稳定产出。

| 属性 | 值 |
|------|-----|
| 目标用户 | 团队开发者 |
| 复用频率 | 高（每次迭代/新成员入职/代码审查前） |
| 输出稳定性 | 稳定（固定产出 schema：manifest.json + index.md + 维度文档） |
| 证据门槛 | 每个结论需 `file:line` 引用 |
| 并行策略 | 架构+组件+API+编码 四维度并行，UI+模式+观察 依赖前序结果 |
| 质量门 | 所有维度完成后通过 `index.md` 一致性检查 |

## `incremental`

仅分析 git 变更部分，更新已有知识文档。

| 属性 | 值 |
|------|-----|
| 目标用户 | 日常开发的增量更新 |
| 复用频率 | 中（每次提交后 / daily） |
| 输出稳定性 | 追加式，不覆盖已有文档 |
| 证据门槛 | 对比标记 `[NEW]/[CHANGED]/[REMOVED]/[CONFIRMED]` |
| 并行策略 | 仅变更涉及的维度，串行优先（变更量小） |
| 质量门 | 不覆盖已有规则，`rules/` 中已确认规则不再重复提议 |

## `development`

skill 作者调试和迭代模式。

| 属性 | 值 |
|------|-----|
| 目标用户 | skill 开发者 |
| 复用频率 | 低（开发/调试阶段） |
| 输出稳定性 | 不稳定（可能输出 debug 信息） |
| 证据门槛 | 放宽（允许标注"模式推断"无法验证的场景） |
| 并行策略 | 单维度串行，每维度完成后暂停确认 |
| 质量门 | 仅需产出物格式正确，不强制完整性 |
